# 交互对话、单次提问与管道分析

根据日常终端排障场景的不同，`aist` 提供以下核心工作流。

## 1. 交互式排障模式

在标准终端直接运行 `aist` 进入多轮会话：

```bash
aist
```

也可以带上首个问题直接开场，进入连续排障：

```bash
aist "api.example.com 返回 502，帮我检查 Nginx 和后端上游服务状态"
```

单轮排障自动闭环机制：
1. 模型按需发起 `shell_execute`、`memory_search`、`memory_save` 或 `file_edit` 工具调用；
2. 遇到执行命令或修改文件时，终端弹出三选一确认菜单：
   - **执行 / 是**：在终端执行该步骤并将真实输出送回模型继续分析；
   - **跳过此命令 / 否**：仅跳过当前这一步，继续处理同批次后续步骤；
   - **拒绝全部，由我补充说明**：立即停止本轮剩余需确认的操作并回到输入框，方便你纠正排查方向或补充线索。
3. 单轮最多自动连续推进 **25 轮工具调用**（`DefaultMaxFollowUps = 25`）；达到上限后会自动暂停，输入“继续”即可接着执行。
4. 模型思考期间按 `Esc` 可随时取消当次请求而不丢失历史消息；在输入框按 `Ctrl+C` 保存会话并退出。

## 2. 管道只读分析模式（Pipe Mode）

通过管道把日志、报错堆栈、K8s 事件或变更 Diff 直接喂给 `aist` 分析后退出：

```bash
kubectl describe pod api-7d9f8b-xk2lp -n prod | aist "为什么一直 CrashLoopBackOff？"
journalctl -u postgresql --since "30 min ago" | aist
git diff HEAD~1 | aist "检查有没有高风险生产配置改动"
```

管道模式特点：
- **严格只读、分析即退**：管道模式下请求不挂载任何执行或写文件工具，分析结果直接输出到终端后立即退出，适合嵌入日常命令行流水线；
- **大文本吞吐保护**：最多从标准输入读取 **1.6 MB**，送入模型前保留最多 **24 万字符**（超长时保留头尾关键上下文），同时自动结合本机环境记忆目录；
- **问题可省略**：直接执行 `cmd | aist` 时，默认对输入内容做异常诊断与根因提炼。

## 3. PTY 实时交互与非分页执行环境

在交互模式下确认执行命令时：

- **原生 PTY 直通终端**：有终端时命令运行在真实 PTY 中（远端主机使用 `ssh -t`）并实时同步窗口尺寸。遇到 `sudo` 密码、SSH 私钥口令、MFA 二次验证或 `[y/N]` 确认时，直接在终端原位输入即可——**切勿把密码或验证码粘贴进聊天框**。
- **自动防分页卡死**：执行环境自动注入 `PAGER=cat`、`GIT_PAGER=cat`、`SYSTEMD_PAGER=cat`、`MANPAGER=cat` 以及 `EDITOR=false`、`VISUAL=false`、`GIT_EDITOR=false`、`SUDO_EDITOR=false`，避免 `systemctl status`、`git log` 等命令卡在交互分页器里。
- **超时与内存上限保护**：单条命令默认超时 30 分钟（输出流结束后保留 5 秒退出宽限），客户端内存最多缓存命令输出的前后各 512 KB（共 `1 MiB`），回传给模型时保留最关键的前 60% 与后 40%（共 8000 字符上限）。
